# T3 route

These notes describe intent. Where they differ from the current tool schemas and harness rules, the tools and rules win.

- Call `orchestrator_capabilities` before the first `delegate_task`, and again after an error or when the user names a different provider. Use model IDs it lists and put settings in `target.options`.
- Use native subagents for same-provider work you wait on in the same turn. Use `delegate_task` for the other provider, requested settings, background work, or a tool-managed worktree. Don't create a child's checkout yourself or open top-level threads for reviews.
- Give each review a bounded, read-only task with no nested agents. Council reviewers work independently before you combine their findings.
- Keep task IDs and follow the returned `next`. If completion wakes the parent, end the turn instead of polling, sleeping, or watching. Read the result when notified, and say plainly when a task is blocked on a question or an approval.
- Report requested providers or models that aren't available. Don't substitute another or fall back to shell CLIs. Cancel replaced or unneeded tasks with `task_cancel`.
- Start each new review or re-check with a fresh `delegate_task`, not a thread message. Fix small findings yourself. When given a thread ID, read the thread before describing it and use the returned link.
