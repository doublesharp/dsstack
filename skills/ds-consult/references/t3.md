# T3 route

Use current tool schemas and harness rules; these notes describe the routing intent.

- Discover delegation tools and call `orchestrator_capabilities` before the first `delegate_task`; refresh after an error or user-named provider change. Preserve available model IDs and put settings in `target.options`.
- Use native subagents for the same provider/model settings when waiting in-turn; use `delegate_task` for another provider, requested settings, background work, or tool-owned worktree isolation. Never manufacture a child's checkout or create top-level threads for reviews.
- Set a bounded review task, read-only by default, with no nested agents. A council's reviewers work independently before synthesis.
- Retain task IDs and follow returned `next`. If completion will wake the parent, end the turn without polling, sleeps, watchers, or status loops. Read the completed result when notified; identify blocked questions/approvals honestly.
- Unavailable requested providers/models must be reported. Do not silently substitute or fall back to shell CLIs. Cancel replaced/unneeded tasks through `task_cancel`.
- A new delegate review/re-check uses a fresh `delegate_task`, not a thread message. Fix small findings locally. When given a thread ID, read it before describing its contents and use the returned link.
