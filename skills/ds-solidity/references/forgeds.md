# forgeds toolchain, caching, and coverage

Use [`forgeds`](https://github.com/doublesharp/foundry/blob/402b5f166132929d556f431dd3d8f9ccb698e99d/FORGEDS.md), the doublesharp Foundry fork, for local development and CI builds, tests, fuzzing, invariants, and coverage through project wrappers.

- **Paths and wrappers:** `forgeds` defaults to `forgeds-out/` and `forgeds-cache/`, overriding TOML paths. Preserve consumer artifact paths with explicit `--out`/`--cache-path` or environment overrides, ignore generated folders, and route nested `forge` calls (such as from Slither) through the same wrapper.
- **Installation:** prefer the project's pinned [prebuilt `forgeds` asset](https://github.com/doublesharp/foundry/releases/tag/forgeds); verify its SHA-256 and full `Commit SHA`. If unavailable for the platform, build package `forge` at the pinned fork revision with `--locked --bin forgeds` and its required features. Install Solar with `cargo install solar-compiler --locked`, honoring its project pin. Resolve both from Cargo's bin directory. Use `sccache` with `CARGO_INCREMENTAL=0` for Rust source builds; `RUSTC_WRAPPER` only affects Rust builds, not solc/Solar.
- **Compiler caching:** keep shared compiler results at `~/.foundry/cache/compilers` enabled across worktrees; preserve source names and settings, and avoid routine forced or clean builds. Restore and save this cache in CI alongside project caches. Optional [runtime sccache storage](https://github.com/doublesharp/foundry/blob/4ca15fcba25aa61a1b436d28b428e30b459f3d56/docs/dev/solidity-compiler-cache.md) uses `FORGEDS_SCCACHE=1` with a running `sccache` 0.19.0 TCP daemon and its configured CI backend. Verify `sccache_hit` with `RUST_LOG=foundry_compilers::compiler_cache=trace`; ordinary `sccache` compiler counters exclude these operations.
- **Changed-only warnings:** for fork-enabled projects, set `compiler_warnings = "changed"` under `[profile.default]` in `foundry.toml`, inherited by local and CI profiles. Check that the pinned fork supports it. This summarizes warnings from unchanged sources while keeping errors and denied warnings visible; use `"all"` when investigating all diagnostics.
- **Solar and instrumented coverage:** use `forgeds build --use solar` and `forgeds test --use solar` for compatible local and CI development checks with the project's Solidity/EVM settings; keep the approved compiler for deployed bytecode, required coverage, and release artifacts. Use `forgeds coverage --instrumented` for compatible coverage iteration: it preserves optimizer/viaIR settings and reuses compiler output on unchanged reruns with solc or Solar while still running tests and coverage analysis. Probes change bytecode and gas, so use ordinary builds for deployment and gas measurements, and keep project-required coverage modes. Add `--report gaps --report-file <disposable-output>/coverage-gaps.json` for a compact JSON list of uncovered source items.
