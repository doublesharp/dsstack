# Solidity contract changes

- Use [`forgeds`](https://github.com/doublesharp/foundry/blob/402b5f166132929d556f431dd3d8f9ccb698e99d/FORGEDS.md), the doublesharp Foundry fork, for local development and CI builds, tests, fuzzing, invariants, and coverage through project wrappers. Its default `forgeds-out/` and `forgeds-cache/` override TOML paths; preserve consumer paths with explicit `--out`/`--cache-path` or environment overrides, and ignore generated folders. Route nested `forge` calls through the same wrapper.
- Prefer the project's pinned [prebuilt `forgeds` asset](https://github.com/doublesharp/foundry/releases/tag/forgeds); verify its SHA-256 and full `Commit SHA`. If unavailable for the platform, build package `forge` at the pinned fork revision with `--locked --bin forgeds` and its required features. Install Solar with `cargo install solar-compiler --locked`, honoring its project pin. Resolve both from Cargo's bin directory. Use sccache with `CARGO_INCREMENTAL=0` for Rust source builds.
- Keep shared compiler results at `~/.foundry/cache/compilers` enabled across worktrees; preserve source names and settings, and avoid routine forced or clean builds. Restore/save this cache in CI alongside project caches. Optional [runtime sccache storage](https://github.com/doublesharp/foundry/blob/4ca15fcba25aa61a1b436d28b428e30b459f3d56/docs/dev/solidity-compiler-cache.md) uses `FORGEDS_SCCACHE=1` with a running sccache 0.19.0 TCP daemon and its configured CI backend. Verify `sccache_hit` with `RUST_LOG=foundry_compilers::compiler_cache=trace`; ordinary counters exclude these operations. `RUSTC_WRAPPER` only affects Rust builds.
- For fork-enabled projects, set `compiler_warnings = "changed"` under `[profile.default]` in `foundry.toml`, inherited by local and CI profiles. Check the pinned fork supports it. This summarizes warnings from unchanged sources while keeping errors and denied warnings visible; use `"all"` when investigating all diagnostics.
- Use `forgeds build --use solar` and `forgeds test --use solar` for compatible local and CI development checks with the project's Solidity/EVM settings. Keep the approved compiler for deployed bytecode, required coverage, and release artifacts.
- Use `forgeds coverage --instrumented` for compatible coverage iteration: it preserves optimizer/viaIR settings and reuses compiler output on unchanged reruns with solc or Solar; tests and coverage analysis still run. Probes change bytecode and gas, so use ordinary builds for deployment and gas measurements. Keep project-required coverage modes. Add `--report gaps --report-file <disposable-output>/coverage-gaps.json` for a compact JSON list of uncovered source items to guide the next tests.
- Require 100% production-contract line, statement, function, and branch coverage. Check success, rejection, boundaries, adversarial paths, accounting, permissions, state transitions, and upgrade storage layouts. Run focused tests while editing, then required coverage, fuzzing, and stateful invariants with reproducible seeds and project run/depth settings. Report uncovered or uninstrumentable paths; do not exclude production code or weaken properties to claim full coverage.
- Run Slither with the project's actual compiler, dependencies, and remappings. Investigate findings, fix confirmed defects, and explain false positives rather than blanket-suppressing warnings. Report unavailable analysis as incomplete.
- Prefer `@0xdoublesharp/abi-typegen` for new bindings; keep a different existing generator unless the task migrates it. After ABI changes, rebuild, regenerate and check bindings, and check affected consumers. With abi-typegen, use `abi-typegen generate`, then `abi-typegen generate --check`, matching the consumer's target. Do not hand-edit output. Typegen subcommands require project shell integration.
- Pin fork tests to a chain and block. Missing archive data leaves a check incomplete; it never counts as zero. Any reachable fund-loss, authority takeover, or blocked-recovery path is must-fix regardless of rarity.
- Use the requested audit tooling rather than rebuilding its workflow.
