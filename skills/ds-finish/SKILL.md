# Request-complete handoff

Verify the named checkout and reconcile requested outcomes with the final diff and acceptance evidence. Remove accidental scope expansion and scaffolding; preserve unrelated user and worker changes.

Read results from the checks required by the changed behavior and integration boundary. Reuse applicable evidence, rerunning when material edits invalidate it. Broaden only for a concrete concern; preserve mandatory integration and release gates.

Resolve review findings or give evidence-backed dispositions. Distinguish source, fixture, artifact, browser, database, native/runtime, provider, financial, deployment, and production proof. An unavailable required check remains open. If a necessary outcome is blocked, report the partial result and exact dependency rather than completion.

Clean only authorized, task-owned disposable output after checking ownership and open processes. Preserve shared caches and active work. Keep bulky evidence on Scratch and short maintained summaries in Git.

State what changed and why, actual verification, material limits, and remaining gates with owners. Finished means the authorized result is complete and ready for review. This skill adds no push, merge, deployment, messaging, or deletion authority; follow existing authorization without adding ceremonial approval checkpoints.
